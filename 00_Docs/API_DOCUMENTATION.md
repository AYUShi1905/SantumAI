# Santum AI RAG Service - API Specification & Integration Guide

This document provides the authoritative API specification for the Santum AI FastAPI service.

**Base API URL:** `http://localhost:8000/api/v1` (Default local development)  
**Root Health URL:** `http://localhost:8000/health`  
**API Version:** `1.0.0`

---

## 1. Chat & Reasoning

### **POST /chat/stream** (Production RAG)
Streams an empathetic, real-time AI response grounded in retrieved counseling manuals using Server-Sent Events (SSE). It performs parallel safety auditing, classification routing, and selective RAG queries.

#### **Request Body Schema (`ChatRequest`)**
```json
{
  "message": "I've been feeling very anxious lately about my job.",
  "chat_history": [
    {"role": "human", "content": "Hi"},
    {"role": "ai", "content": "Hello! How can I support you today?"}
  ],
  "history_summary": "The user previously discussed their career goals and general life stressors.",
  "plan_level": "premium",
  "remaining_tokens": 1000,
  "happiness": 5.0,
  "stress": 7.5,
  "energy": 4.0
}
```

#### **Fields Description**
*   `message` *(string, required)*: The current user input/question.
*   `chat_history` *(array of ChatMessage, optional)*: The last few messages in the conversation (role: "human" or "ai"). *Note: The backend automatically restricts processing to the last 6 messages to prevent context bloat.*
*   `history_summary` *(string, optional)*: A condensed summary of older parts of the conversation.
*   `plan_level` *(string, required)*: `"free"`, `"standard"`, or `"premium"`.
    *   *Free:* Input limit of 80 words. Retrieves only Santum.net FAQ. Attempting to retrieve restricted CBT exercises triggers an automatic soft upgrade message.
    *   *Standard:* Input limit of 100 words. Retrieves up to `k=2` chunks from standard CBT manuals.
    *   *Premium:* Input limit of 120 words. Retrieves up to `k=3` chunks from all CBT manuals.
*   `remaining_tokens` *(integer, optional, default: 0)*: User's token balance. If `<= 0`, the endpoint refuses to process.
*   `happiness` *(float, optional, default: 5.0)*: User mood scale `[0.0 to 10.0]`.
*   `stress` *(float, optional, default: 5.0)*: User mood scale `[0.0 to 10.0]`.
*   `energy` *(float, optional, default: 5.0)*: User mood scale `[0.0 to 10.0]`.

---

#### **Stream Lifecycle & Response Format**
The endpoint returns a Server-Sent Events text stream (`text/event-stream`). It streams words as they are generated by OpenAI. The final chunk of the stream is always a JSON metadata block separated from the text content by two newlines (`\n\n`).

#### **Token Billing Formula**
To protect user balances, the RAG service charges only for the core interaction:
$$\text{Charged Tokens} = \text{Tokens}(\text{User Message}) + \text{Tokens}(\text{AI Response})$$
System instructions, RAG context vectors, and historical memory messages are excluded from the user's token charges.

#### **Example Stream Completion Metadata (Success)**
```json
{
  "total_tokens": 145,
  "status": "completed",
  "model_used": "reasoning",
  "plan": "premium",
  "mode": "rag_complex"
}
```

#### **Example Stream Completion Metadata (Safety Violation)**
```json
{
  "total_tokens": 35,
  "status": "safety_violation",
  "category": "self-harm",
  "model_used": "moderator",
  "mode": "safety_refusal"
}
```

#### **Integration Code Example (Python Listener)**
The following script demonstrates how to connect to the stream, display the output in real-time, and extract the billing metadata at the end of the stream.

```python
import requests
import json

payload = {
    "message": "I'm feeling a bit anxious today.",
    "chat_history": [],
    "plan_level": "premium",
    "remaining_tokens": 1000,
    "happiness": 5.0,
    "stress": 7.0,
    "energy": 5.0
}

response = requests.post(
    "http://localhost:8000/api/v1/chat/stream", 
    json=payload, 
    stream=True
)

for chunk in response.iter_content(chunk_size=None, decode_unicode=True):
    if "\n\n{" in chunk:
        text_part, metadata_part = chunk.split("\n\n{")
        print(text_part, end="", flush=True)
        # Parse the JSON metadata payload
        metadata = json.loads("{" + metadata_part)
        print("\n\n--- METADATA ---")
        print(json.dumps(metadata, indent=2))
    else:
        print(chunk, end="", flush=True)
```

## 2. Ingestion Pipeline

### **POST /ingest/file**
Uploads a document (PDF or DOCX), processes its contents, strips headers/footers, and streams vectors to Qdrant. **Note: The embedding process runs asynchronously in background tasks.**

*   **Request Content-Type:** `multipart/form-data`
*   **Parameters:**
    *   `file` *(Binary, required)*: The PDF or DOCX file.
    *   `is_cbt_manual` *(boolean, optional, default: false)*: Set to `true` to flag this manual as restricted CBT content (requires Premium).
    *   `header_margin` *(float, optional, default: 0.1)*: Top margin percentage ignored during PDF ingestion.
    *   `footer_margin` *(float, optional, default: 0.1)*: Bottom margin percentage ignored during PDF ingestion.

#### **Response Payload (`IngestResponse`)**
```json
{
  "message": "File accepted for processing. Ingestion is running in the background.",
  "filename": "cbt_manual.pdf",
  "chunks_processed": 42,
  "status": "success"
}
```

### **GET /ingest/files**
Lists all unique source filenames currently stored in the vector database.

#### **Response Payload**
```json
{
  "files": [
    "cbt_manual.pdf",
    "general_faq.docx"
  ],
  "count": 2
}
```

### **DELETE /ingest/file**
Deletes all vector points associated with a specific file name.

*   **Query Parameters:**
    *   `filename` *(string, required)*: File name to delete.

#### **Response Payload**
```json
{
  "message": "Successfully deleted data for file: cbt_manual.pdf"
}
```

### **DELETE /ingest/all**
Clears the entire Qdrant vector database collection.

#### **Response Payload**
```json
{
  "message": "Successfully cleared the entire collection"
}
```

## 3. Summarization

### **POST /summarize**
Summarizes a chat history transcript into a concise, professional counselor's summary. Uses the fast background model (`gpt-4.1-mini`).

#### **Request Body Schema (`SummarizeRequest`)**
```json
{
  "chat_history": [
    {"role": "human", "content": "I'm having troubles focusing at work."},
    {"role": "ai", "content": "I understand. Let's talk about what triggers these distractions."}
  ],
  "existing_summary": "The user is working on mindfulness routines."
}
```

#### **Response Payload (`SummarizeResponse`)**
```json
{
  "summary": "The user discussed issues focusing at work. The counselor suggested checking for triggers. The user continues mindfulness routines.",
  "status": "success"
}
```

### **POST /chat/title**
Generates a 3-5 word professional title suitable for naming a chat session in the UI.

#### **Request Body Schema (`SummarizeRequest`)**
```json
{
  "chat_history": [
    {"role": "human", "content": "I'm feeling very sad about the breakup."},
    {"role": "ai", "content": "I'm here for you. Breakups can be incredibly hard."}
  ]
}
```

#### **Response Payload (`TitleResponse`)**
```json
{
  "title": "Breakup Support & Healing",
  "status": "success"
}
```

## 4. System & Observability

### **GET /health**
Returns global service metadata and health status.

*   **URL:** `http://localhost:8000/health` (Root level)

#### **Response Payload**
```json
{
  "status": "healthy",
  "project": "Santum AI RAG Service",
  "version": "1.0.0"
}
```

*   **LangSmith Tracing:** When `LANGSMITH_TRACING=true` is set in the environment, RAG queries (`/chat/stream`) and summarization calls (`/summarize`) are automatically traced under the specified LangSmith project.
